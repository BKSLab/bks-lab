## Этап 1 — backend: контент, БД и API `[x]`

- Слои по `docs/FASTAPI_PATTERNS.md`: api → services → repositories →
  {content | PostgreSQL}; DI в `dependencies/` (шов для

- Markdown-репозитории трёх типов контента (`articles`, `notes`, `projects`):

  `alembic upgrade head` в entrypoint, как в референсе), модели
  `page_views` (+ индексы), `content_items`.

  вне списка), нормализация (query обрезается, якорь `#note-<slug>` →
  `note_slug`), insert через BackgroundTasks (202 сразу), `visitor_hash`
  (HMAC-дневная соль, инъецируемые часы), фильтр ботов, rate-limit,
  IP из forwarded-заголовков.
- `/api/health`: `SELECT 1`, 503 при недоступности БД.
- Скрипты `backend/scripts/new_article.py`, `new_project.py`, `new_note.py`.
- Эндпоинты P0 по `docs/api_contract.md`: `/articles` (+category, +q,
  пагинация), `/articles/latest`, `/articles/{slug}`, `/notes`,
  `/notes/latest`, `/categories`, `/projects` (+featured),
  `/projects/{slug}`.
- Стартовый контент: 6 статей, 3–5 заметок и 3 проекта из дизайн-ТЗ §10–§11
  (тексты могут быть черновыми, frontmatter — полный и валидный).
- Тесты pytest + httpx: контракт каждого эндпоинта, пагинация и её границы
  (`page` вне диапазона → 200 пусто), `q` (min_length, регистр), фильтры,
  404; запись pageview (белый список, якорь → `note_slug`, хэширование,
  боты, rate-limit); синхронизация (рескан по изменённому `os.utime` на
  `tmp_path`-фикстуре; удаление файла удаляет запись; невалидный frontmatter
  исключает из API и проекции; параллельные запросы → один рескан).
  Репозитории БД — на testcontainers, по `docs/FASTAPI_PATTERNS.md`.

**DoD:** все эндпоинты P0 отвечают по контракту на стартовом контенте;
pageview пишется в PostgreSQL, IP в БД отсутствует; `content_items`

## Этап 7 — инфраструктура prod и запуск `[~]`

- Мультистейдж Dockerfile фронтенда (standalone, non-root; билд без живого
  backend — graceful fallback `lib/api`), Dockerfile бэкенда уже с этапа 0
  (entrypoint: `alembic upgrade head` + hypercorn, 1 воркер; для prod
  дополнить: non-root user, EXPOSE).
- Один nginx: TLS, `/api/*` → backend (включая `/api/admin/*`), всё
  остальное (включая `/admin`) → frontend, `X-Forwarded-For`/`X-Real-IP`,
  envsubst-шаблон, certbot (webroot), редирект 80→443;
  **security-заголовки только в nginx** (CSP сначала `Report-Only`, HSTS,
  X-Frame-Options); для `/admin` — более строгий CSP без доменов РСЯ.
- docker-compose prod: сервисы db/backend/frontend/nginx/certbot,
  healthchecks, volumes (`pg_data`, `content/`, сертификаты); порт БД
  наружу не публикуется.
- Деплой на bks-lab.ru, `metadataBase` на боевой домен. Deploy-скрипт
  `scripts/publish-content.sh [--pull]`: обновление Markdown, синхронизация
  backend, POST `/api/revalidate` с секретом в Authorization, прогрев
  страниц и sitemap (публикация без пересборки).
- **РСЯ:** заявка на модерацию площадки; после одобрения — выбор форматов
  и фиксированных высот слотов (вписать в `docs/architecture.md` §4),
